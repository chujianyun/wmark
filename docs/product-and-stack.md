# Wmark：跨平台水印工具设计

日期：2026-09-09。当前目录为新项目；本方案暂按「图片优先、离线处理、个人用户与内容创作者」设计，待产品范围确认。交付物是界面原型与技术选型，不是已完成的桌面客户端。

## 产品与范围

定位：拖入图片，调整一次水印，批量导出副本。适用于摄影署名、证件用途说明、电商样片。

首期支持 JPG、PNG、WebP，文字水印与图片 Logo、透明度、旋转、九宫格定位、全图平铺、可保存模板、批量导出。提供中文字体并检查字体许可证。动态图片明确拒绝或提醒转为静态，不静默丢帧。HEIC、RAW、PDF、视频在后续独立评估；不能因为底层某个库支持格式，就直接承诺完整产品支持。

默认本地处理，无账号、无图片上传。水印用于署名和标注用途，不承诺防盗图或阻止证件滥用。

## 界面原型

打开 ../prototype/index.html，无需安装依赖。原型可导入多张图片、选择图片、调整文字/Logo、字体、颜色、透明度、大小、旋转和位置、平铺、按住比较原图、套用三个模板、保存一套文字模板、导出当前 PNG。示例图为本地 Canvas 绘制，无远程素材请求。

原型保存的模板位于当前浏览器 localStorage；正式版迁移到应用配置。Logo 与图片文件不持久化。原型 Canvas 使用浏览器字体与编码，不代表正式版渲染精度、性能与色彩管理。当前不包含桌面窗口、目录选择、批量任务执行、历史任务或多模板管理。

### 布局

- 顶栏：品牌、离线状态、导入入口。Mac 保留原生窗口控制区域；Windows 使用原生系统标题栏与窗口按钮。
- 左侧 236px：图片缩略图、文件名、尺寸、当前选中状态、添加图片。正式版增加移除、全选、失败标记和列表虚拟化。
- 中间弹性区：最大化图片预览、尺寸信息、原图对比、快捷模板。正式版增加缩放、拖动定位与键盘微调。
- 右侧 304px：文字/图片类型、内容、字体、比例、透明度、颜色、平铺、旋转、位置、导出入口。
- 底栏：任务状态。正式版显示处理队列进度、取消入口和失败数。

视觉：暖白底、低饱和绿色主色 #25755E、12px 工作区圆角、清晰细分割线。中性系统字体适配两端，只有水印本身使用固定字体文件。主按钮固定用于导出，导入是次级按钮。

### 正式版完整流程

1. 空状态：中央拖放区 + 选择图片按钮 + 支持格式，选择后进入工作台；不预装示例图。
2. 导入：读取尺寸、方向和格式，生成缩略图；坏文件单独标记，其余继续。
3. 编辑：设置默认作用于整个批次，列表切换只切换预览；明确显示“应用于全部 N 张”。后续再考虑单图覆盖，首期避免混淆。
4. 导出设置弹窗：范围（全部/选中）、输出目录、保持原格式/JPG/PNG/WebP、质量（仅有损格式）、文件后缀、移除位置信息（默认启用）。默认另存到 wmark-output，保留原图，重名自动编号。
5. 任务进行中：显示已完成数量、当前文件与整体进度；允许取消，保留已完成结果；不影响界面操作，但导出使用开始时的参数快照。
6. 完成：成功/失败数量、打开输出目录、查看失败原因、仅重试失败项。取消单独作为状态，不伪装成失败或成功。

导出尺寸默认保持原图。透明图片转 JPG 时显示背景色选项，默认白色。原型仅提供当前 PNG 下载；上述弹窗与队列是下一阶段设计。

## 技术方案比较

| 路线 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| Tauri 2 + React + Rust | 复用系统 WebView；文件处理与界面分离；适合本地桌面工具 | Rust 学习成本；两端 WebView 差异；需验证字体与颜色 | 推荐，适合长期维护 |
| Electron + React + sharp | JS/TS 团队开发直接；成熟 Node 图像生态 | 打包包含 Chromium/Node；原生依赖须按架构打包 | 如果团队不熟悉 Rust，优先用这条路线降低交付风险 |
| Flutter + Dart + 原生图像模块 | 跨端 UI 一致，可扩展移动端 | 桌面图片处理与原生库集成仍需投入 | 已有 Flutter 团队时考虑 |

体积、内存和批量耗时均需通过样机实测，不预先给无依据的数值承诺。

## 推荐栈

| 层 | 选择 | 用途 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | 原生窗口、文件选择、拖放、受控文件访问、安装包 |
| UI | React + TypeScript + Vite | 工作台与导出交互 |
| 样式与基础组件 | Tailwind CSS + Radix UI + Lucide | 可访问表单、对话框、图标 |
| 状态 | Zustand | 当前批次、模板、编辑参数和任务状态 |
| 核心 | Rust | 参数校验、作业调度、图像合成、文件写入 |
| 图像 | image + tiny-skia；字体采用 rustybuzz + fontdb/fontdue 方案验证 | 解码编码、旋转与透明合成、字体查找、整形及栅格化 |
| 配置 | Tauri store / 带版本的 JSON | 设置与模板；首期无需数据库 |
| 测试 | Vitest + Rust tests + 两端集成验收 | 参数映射、渲染一致性、导出失败与取消 |
| 构建 | GitHub Actions 的 macOS / Windows runner | 分平台编译、签名、安装验证 |

imageproc 可用于基础文字绘制，但不能把基础 draw_text 当作完整中文字体回退、复杂文字排版和旋转排版方案。字体、ICC 色彩转换、EXIF 方向、透明度编码在技术样机阶段验证，必要时加入专用色彩/元数据库。首期建议统一转换为 sRGB 输出，在产品说明中明确非广色域无损工作流。

## 数据流与边界

UI 发送文件句柄/受控路径和 WatermarkSpec；Rust 负责读取、解码、方向校正、色彩归一化、合成与写入。避免通过 IPC 反复传输全尺寸 base64 图片。缩略图和预览用受控资源 URL 返回。

WatermarkSpec 包含 schemaVersion、type、text/logoRef、fontRef、relativeSize、color、opacity、rotation、anchor、marginRatio、tileSpacing。位置、字号和间距都以原图短边比例表达，不直接存预览画布像素。导出任务保存不可变参数快照。

预览与导出共用 Rust 渲染函数与字体文件。交互采用防抖与递增请求 ID，丢弃过期预览；预览按相同比例缩放，最终以原图尺寸渲染。必要时 UI 先显示临时变换，但完成后必须以核心预览替换。

任务队列按估算解码内存限制并发，而不是一次解码全部文件。例如 6000×4000 RGBA 单缓冲约 96MB，旋转、预览、编码会产生额外缓冲。进度按文件完成数呈现；同一文件编码期间可显示阶段状态。取消在安全阶段检查，并清理未完成的临时输出。

输出先写目标目录临时文件，成功后原子重命名。目录不可写、磁盘满、坏图片、缺失字体分别给明确原因。失败日志不包含图片内容，路径显示仅用于本地问题定位。

Tauri capabilities 仅开放所需命令；对传入路径、参数范围、超大文件、格式和输出文件名做校验，不开放任意 shell 执行。远程页面不能调用本地处理命令。

## 跨平台发布与验收

macOS：Apple Silicon 和 Intel 构建，DMG；正式分发需签名及公证。Windows：先支持 x64，NSIS 安装包；处理 WebView2 runtime，安排代码签名。Windows ARM64 根据用户需求另行验证。Tauri 的 Mac 使用 WKWebView、Windows 使用 WebView2，不能只在 Chrome 中检查界面便声称跨平台通过。

自动更新留作后续，启用前配置签名校验、版本回退策略和独立发布通道。首期无业务后端；发布安装包或更新会引入下载托管，不需要图片服务器。

重点验收：横竖图的同位置效果；高 DPI；中文及中英文混排；EXIF 旋转；透明 Logo；超长文字；旋转后的安全边距；不同尺寸平铺；元数据移除；输出重名；不可写目录；取消后重试；100 张混合尺寸批次内存。两端导出结果用固定字体与输入做像素差异检查；编码差异与抗锯齿容差应分别设定。

## 建议实施顺序

1. 确认图片优先与原型布局；补齐空状态、导出设置、任务结果界面。
2. 技术样机：两端单图导入、中文文字与 Logo、核心预览与导出一致性、色彩方向验证。
3. 批量队列、取消重试、模板与目录导出。
4. 真机体验、安装签名、高 DPI、性能验证后发布。
